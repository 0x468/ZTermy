# Ztermy Netcatty / Nebula 对齐计划

日期：2026-09-02

状态：执行中

基线：ztermy `0.4.4`；Nebula 固定参考快照 `f4314a8d68b653e5cac1930eae3467c4af786c36`

详细差异证据见 [Kuddev/nebula 与 ztermy 源码级对比报告](reviews/nebula-comparison-2026-09-02.md)。

## 1. 产品边界

本计划只增强 ztermy 自己的 Windows 11 原生 SSH 工作台和内置供应商 AI 助手。以下内容永久排除：

- 外部 Agent/CLI 集成，包括 Codex、OpenCode、Claude Code 及同类 harness；
- Git 面板或 Git 工作流宿主；
- 在线更新检测；
- 复制第三方源码、图标、主题、品牌或其他资产。

Nebula、Netcatty 和其他产品只提供行为与体验参照。实现必须由 ztermy 自己设计，并遵守项目既有架构、许可边界和 Windows 原生约束。

## 2. 推进节奏

采用 `milestone` 节奏：

- 每项能力开始前先核对参考产品、现有代码路径和可测验收条件；
- 迭代期间运行最小覆盖的编译、单元测试、QML/翻译/资产门禁和运行时 smoke；
- 每个阶段末运行相邻集成测试；
- Netcatty 数据侧栏、Nebula 终端效率和最终重构三个里程碑执行 Debug + static Release 全量门禁；
- UI、IME、终端延迟和 Windows 原生行为必须保留人工运行证据，不能只凭单元测试宣布完成。

## 3. 执行顺序

### N1：已知主机中心

目标：把当前仅供握手内部使用的 `known_hosts.json` 提升为用户可管理的数据中心。

- [x] 工作台新增“已知主机”侧栏入口；
- [x] 列出主机、端口、算法、SHA-256 指纹和公钥；
- [x] 搜索、刷新、复制指纹/公钥、逐条删除和清空；
- [x] 导入当前用户的 OpenSSH `known_hosts` / `known_hosts2`；
- [x] 支持选择任意 OpenSSH known_hosts 文件；
- [x] 导入结果明确区分新增、重复、冲突、不支持和跳过项；
- [x] 不以导入内容静默覆盖 ztermy 已信任但密钥不同的条目；
- [x] 文件读取和写入不阻塞 Qt Quick GUI/渲染线程；
- [x] 覆盖解析、去重、冲突、存储失败、删除和 UI smoke。

实现记录（2026-09-03）：默认扫描当前用户的 `known_hosts`、`known_hosts2` 和 Windows
ProgramData OpenSSH 文件，也可导入任意文件；列表使用虚拟化视图并保留同一端点的多种算法记录。
所有管理操作在单独工作线程执行，存储层的合并、删除和清空是进程内事务，避免与 SSH 首次信任写入互相
覆盖。哈希主机名、通配符、否定模式和 OpenSSH marker 因无法安全还原为可连接端点而作为“不支持”明确
计数，不伪装成普通主机。已通过解析/冲突/存储失败/事务变更单测、目标 `clang-tidy`、QML/翻译门禁，
以及真实窗口的明暗主题、紧凑/常规布局和键盘冒烟；最终仍随整批功能由产品所有者统一验收。

### N2：钥匙串与身份中心

目标：替换当前按 Profile 重复展示密码/密钥路径的“凭证”页面。

- [x] 建立可复用身份模型，身份与 Profile 引用分离；
- [x] 新建密钥对；
- [x] 导入现有私钥、公钥和证书；
- [x] 新建身份并组合用户名、认证来源和可选证书；
- [x] 展示哪些 Profile 正在引用身份，删除前处理引用关系；
- [x] 支持 SSH agent 身份来源，不复制 agent 内私钥；
- [x] 现有 Profile 配置兼容迁移，不丢失凭据或密钥路径；
- [x] “凭证”侧栏更名为“钥匙串”。

实现记录（2026-09-03）：新增独立 `keychain.json` 目录模型，密钥/证书与身份分层，Profile
仅保存身份引用；既可由 Windows OpenSSH 生成 ED25519/RSA/ECDSA 密钥，也可复制导入或只引用
现有私钥和 OpenSSH 用户证书。身份组合用户名、密码/密钥/证书/agent 认证来源，主机编辑器可直接
选择并复用。旧 Profile 首次加载时执行可重入迁移，保留原凭证引用和密钥路径，未知的旧密钥算法
明确标记为 unknown。受管密钥删除时只清理 ztermy 钥匙串目录内文件，外部引用永不删除；仍被身份或
Profile 引用的记录拒绝删除。相关领域、存储、迁移、控制器、连接解析和 QML/翻译聚焦门禁已覆盖，
真实窗口证据与 Netcatty 数据侧栏里程碑的全量门禁在 N3 完成后统一执行。

### N3：连接日志与审计界面

目标：从“给打开的 Tab 开关原始日志”提升为可检索的连接历史与日志中心。

- [x] 按会话展示日期、时段、本机用户/设备、目标主机、协议、用户名和状态；
- [x] 支持进行中、成功、失败、断开、重连等状态；
- [x] 搜索、日期筛选、主机筛选、收藏与详情；
- [x] 会话详情关联原始日志文件、连接阶段、失败原因和可用诊断；
- [x] 原始终端记录仍坚持显式选择目的文件，不把所有终端内容默认落盘；
- [x] 历史列表有上限、分页/增量加载和清理策略；
- [x] 日志写入与查询不得阻塞终端 I/O 或界面线程。

实现记录（2026-09-03）：新增独立 `connection-history.json`，本地与 SSH 会话开始后自动记录
连接元数据，跟随 SSH phase/failure/reconnect 与本地进程状态更新；异常退出遗留的进行中记录在下次
启动时标为“已中断”，不会伪装成仍在线。日志中心支持全文、ISO 日期、精确主机和收藏筛选，默认
30 条并按批增量加载；最多保留 1000 条未收藏和 2000 条总记录。详情展示连接阶段、失败原因、本机
来源及显式开启的原始日志路径。元数据快照在单线程后台队列顺序写入，原始终端字节仍只进入原有的
手动 SessionLogWriter。连接历史单测、应用编译、QML 格式/静态检查及 2195 条翻译门禁已通过；
真实窗口和全量静态分析在本里程碑收口时执行。

### N4：终端选区快捷浮窗专项

目标：把现有“添加到 AI”单一浮窗变成可配置、低干扰的选区快捷入口。

- [ ] 设置页允许启用或永久关闭选区浮窗；
- [ ] 用户可配置动作顺序，并选择动作直接显示还是收进“更多”；
- [ ] 每个动作使用资源化小图标，并提供名称和悬浮说明；
- [ ] 每个动作声明执行后是否保留选区，复制等动作按设置处理，AI/搜索类动作默认可保留；
- [ ] 新增“隐藏本次浮窗”，只影响当前选区，不清除选区；
- [ ] 空闲超时后降低不透明度，鼠标进入时恢复清晰，不自动触发动作；
- [ ] 根据选区由上向下或由下向上形成的方向，把浮窗优先放在选区外侧；
- [ ] 遇到上下边界时自动翻转或钳制，并保留本次隐藏作为兜底；
- [ ] 键盘选择、鼠标拖选、滚动、窗口缩放和 DPI 改变时位置稳定；
- [ ] 覆盖选择保留策略、菜单配置迁移、单次隐藏和边界避让测试。

### N5：Nebula 终端效率能力

以下为用户明确选择的范围，按依赖关系拆成小阶段：

#### N5.1 输入与发现

- [ ] Ghost text 与补全候选；
- [ ] 持久命令历史索引；
- [ ] 统一命令面板。

补全数据优先来自当前 Shell 历史、ztermy 脚本/快捷命令和当前 Profile；不得阻塞输入路径。命令面板复用现有 ActionRegistry，不建立第二套快捷键真源。

#### N5.2 Tab 与 Pane 交互

- [ ] Tab 分页、溢出菜单和拖动到边缘时自动滚动；
- [ ] Pane header；
- [ ] 拖拽分屏；
- [ ] Pane 脱离窗口、重新附着与缩放。

必须保持 Snap Layouts、自定义标题栏命中测试、每 Tab 置顶和全局置顶的既有语义。

#### N5.3 工作区连续性

- [ ] 工作区导入导出；
- [ ] 恢复失败隔离；
- [ ] 崩溃循环保护。

导入必须版本化和校验；恢复失败只隔离有问题的会话/Pane，不清空全部工作区。

#### N5.4 SSH 与文件工作流

- [ ] OpenSSH 配置导入与同步；
- [ ] 远程文件抽屉与终端目录跟随；
- [ ] 本地文件抽屉。

OpenSSH 导入覆盖 `Host`、`HostName`、`User`、`Port`、`IdentityFile`、`ProxyJump` 和常用 include；不承诺无损写回任意用户配置。远程抽屉复用 SFTP 会话/传输队列，不另建阻塞式连接。目录跟随必须显式展示能力降级。

#### N5.5 Shell 覆盖

- [ ] WSL 检测与启动；
- [ ] Nushell 本地会话；
- [ ] Bash、Zsh、Fish、PowerShell、Nushell 的 shell integration 能力矩阵与补齐。

### N6：C++ 规范与重构门禁

- [ ] 采用 [Ztermy C++ 工程规范](CPP_GUIDELINES.md)；
- [ ] 生成文件/类规模报告和依赖方向报告；
- [ ] 优先拆分 `AppController`、超长 QML 页面和多职责平台文件；
- [ ] 重构必须保持行为测试先行，禁止“大爆炸式”全仓改写；
- [ ] 最终运行格式、clang-tidy、QML、翻译、资产、Debug/Release 测试和安装包门禁。

## 4. 里程碑完成定义

每一阶段只有在以下证据齐备时才可勾选完成：

1. 明确的行为契约和失败/空状态；
2. 与变更相称的自动化回归测试；
3. 目标构建通过且无新增静态分析错误；
4. UI 功能具备键盘、鼠标、窄宽度和浅/深主题运行证据；
5. 持久化变更具有旧版真实 fixture、迁移和未来 schema 拒绝测试；
6. 跟踪文档记录实际实现、偏差和剩余人工验收，不用“代码存在”代替完成。
