# ADR 0011: Per-user WiX installer

Status: accepted

## Context

V1 needs an installed distribution in addition to the portable ZIP. The
installed build must launch without a developer toolchain, must not require
administrator privileges for a personal installation, and must preserve
profiles, host trust, and settings across upgrade and uninstall. CPack also
sees install rules contributed by fetched dependencies unless the package
payload is explicitly scoped.

The project license has not been selected. Shipping CMake or WiX placeholder
license text, or presenting it as an agreement, would misrepresent the
project's current status.

## Decision

The installed artifact is an x64, per-user MSI generated by CPack with WiX
Toolset 4.0.4. This requires CMake 4.3 or newer, where CPack gained actual
per-user WiX support. WiX is installed into the ignored `build/tools/wix`
directory and selected through the `WIX` environment variable; it is not a
global developer-machine dependency.

Only the `Runtime` CMake install component is packaged. It contains the
statically linked `ztermy.exe`. Dependency headers, libraries, DLLs, PDBs, and
the portable marker are excluded.

The MSI installs below `LocalAppDataFolder`, creates a current-user Start menu
shortcut, and uses a stable upgrade GUID. Product codes remain generated per
package. Same-version upgrades are allowed during the V1 development cycle so
locally rebuilt `0.1.0` packages can replace one another.

The package uses a small project-owned CPack WiX template without an authored
wizard or license agreement. Windows Installer provides the basic install
interaction. A license page may be added only after the owner selects and
records the actual project license.

Application data remains outside the MSI payload and follows ADR 0009.
Therefore upgrade and uninstall do not remove profiles, known-host trust,
settings, logs, or crash diagnostics.

## Consequences

- Installation is scoped to the current user and does not require elevation.
- The installed application is independent of Qt and OpenSSL runtime DLLs.
- The package payload cannot accidentally grow when a fetched dependency adds
  another install rule.
- Automated builds generate and validate the MSI but never install it.
- Installer lifecycle, Start menu behavior, upgrade, uninstall, and data
  retention require a manual Windows 11 acceptance pass.
- WiX ICE validation currently reports reviewed CPack structure warnings:
  ICE61 for same-version upgrade support, ICE69 for the generated shortcut
  component, and ICE91 for the fixed per-user destination.
