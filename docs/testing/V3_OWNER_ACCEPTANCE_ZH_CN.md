# ztermy V3（0.3.x「糸」）所有者验收单

状态：等待最终静态 Release 候选生成后执行

这份清单只包含自动化测试无法代替的真实交互。未提到的项目视为符合预期；
发现问题时记录步骤、当前模式、Provider/模型、终端类型以及截图即可。不要在反馈中
粘贴 API Key、密码或私钥内容。

## 1. Provider 与模型

- [ ] 打开“设置 > AI”，依次切换 OpenAI、Anthropic、DeepSeek、Kimi、Z.AI、
      Ollama 和 OpenAI-compatible。预期 API 地址与请求预览跟随厂商变化；自定义地址
      仍可编辑。
- [ ] 输入 API Key 并保存。关闭并重启 ztermy 后，界面显示已保存但不回显明文；
      可直接继续请求，也可输入新值替换。
- [ ] 点击“获取模型”。预期按钮不会卡住 UI；成功时模型进入可编辑下拉框，失败时显示
      可理解的认证、网络、TLS 或协议错误，仍可手动填写模型。
- [ ] 对支持推理参数的 Provider/模型切换 Off/Auto/Low/Medium/High。预期只展示适配器
      能真实表达的选项；不支持时禁用并说明原因。

## 2. AI 面板与 Markdown

- [ ] 使用终端工具栏右侧 AI 按钮反复打开/关闭面板，再切换左侧/右侧、拖动宽度至
      最小值。预期所有控件留在侧栏内，没有按钮飞入终端、持续拉伸光标或焦点丢失。
- [ ] 让模型返回标题、嵌套列表、引用、行内代码、代码块、表格和链接。预期结构正确
      渲染，窄面板横向内容被约束且页面可纵向滚动。
- [ ] 点击复制。预期剪贴板得到 Provider 原始 Markdown，而不是 HTML 或被压平的显示文本。
- [ ] 在流式输出时取消，再点击重试；在等待命令结果时重复一次。预期取消立即进入中性
      Cancelled 状态，按钮不假死；Retry 只创建一个新回合，旧回合不会追加迟到文本。
- [ ] Provider 返回可公开的 reasoning summary 时，它显示在独立的折叠区域；没有公开
      reasoning 的 Provider 不伪造“思考过程”或声称读取隐藏思维链。

## 3. 终端上下文与结果完整性

- [ ] 在未安装富 Shell 集成的 Linux SSH 会话询问磁盘使用并允许 Agent 执行 `df -h`。
      预期活动列表不再出现失败的 `wait_command`；Agent 按“帧变化 → 帧空闲 → 读取帧”
      完成观察，能读取视口内的表头和 `/` 分区，不伪造退出码，也不会把视口顶部误判为
      “输出被截断”。若该会话已有 Basic/Rich 生命周期标记，则允许改用 `wait_command`；
      Rich 结果应直接带回完整性字段。
- [ ] 查看“请求上下文”预览，分别移除、固定一个上下文条目。预期实际请求与预览一致，
      每项显示来源、目标和 exact/basic/degraded 证据等级。
- [ ] 选择包含中文、宽字符和组合字符的终端文本后“附加选区”。预期内容没有半字符、
      错位或静默缺失；确有截断时明确标注。

## 4. 五种 Agent 模式

- [ ] Read-only：要求执行命令。预期模型可读取已授权上下文，但写操作得到明确拒绝。
- [ ] Ask：要求执行命令。预期出现精确目标、完整命令和规则选项；“仅本次”执行一次。
- [ ] Edit：普通终端命令仍询问；保存 Runbook 和 SFTP 变更默认自动执行，除非规则覆盖。
- [ ] Auto：终端、Runbook、SFTP 和已审核 MCP 调用不出现意外的逐次确认。
- [ ] YOLO：行为与其字面含义一致，不额外弹出启发式“高危命令”警告；无效 Schema、
      失效会话、预算耗尽等技术错误仍正常阻止执行。
- [ ] 用户直接点击可见的 Run 时命令只执行一次，不出现第二层重复警告。

## 5. 可复用规则

- [ ] 在 Ask 审批卡分别创建 Exact、Prefix、Glob、Regex 和 Any-action 规则，并测试
      Allow/Ask/Deny。
- [ ] “本次”不持久化；“本会话”在终端关闭后消失；保存主机的 Profile 规则只影响该
      Profile；Global 规则重启后仍存在。快速连接和本地终端不提供 Profile 范围。
- [ ] 在“设置 > AI > Agent 权限规则”搜索、禁用、编辑、删除、导出并重新导入规则。
      预期修改立即生效；冲突遵循 Deny > Ask > Allow。
- [ ] 对终端命令、PTY 输入、中断、Runbook、SFTP 上传/下载和 MCP 各测试一条规则。

## 6. 用户输入、长命令与交互程序

- [ ] 让 Agent 运行一个持续数秒的命令，同时直接在终端键入下一条命令。预期无需“取得
      控制权”，两条输入有序执行且不会互相截断。
- [ ] 让 Agent 运行会等待输入的 `read`/`Read-Host`，再由 Agent 通过 PTY 回答。预期
      工具卡保持活动，回答后命令正常结束。
- [ ] 分别运行 `hx`/`vim`、`top`、Pager、REPL 和长驻服务。预期终端渲染、Alt Screen、
      用户键盘和 Agent frame/wait 操作正常；退出后光标与提示符位置正确。
- [ ] 在命令运行时断开 SSH、关闭 Tab 和关闭应用。预期无卡死、崩溃、延迟执行或退出断言。

## 7. SSH 运维能力

- [ ] 在真实 SSH 会话让 Agent 读取系统信息、CPU/内存/磁盘/网络遥测、Shell 历史、
      端口转发状态、脚本和笔记。预期目标始终是当前会话/工作区显式目标，不跨主机串数据。
- [ ] 让 Agent 列出 SFTP 路径、读取一个小文本文件、上传和下载一个临时文件。预期路径、
      大小、截断状态与传输任务一致；取消会真正停止任务而不是只删除 UI 记录。
- [ ] 从成功对话保存 Runbook，重新打开并运行。预期生成用户拥有的 ztermy 脚本，步骤和
      变量可检查、可编辑，不依赖隐藏模型记忆。
- [ ] 对 bash/zsh/fish 和没有 Shell Integration 的连接检查能力徽标。预期无法证明精确
      命令边界时显示 basic/degraded，而不是虚构退出码或 CWD。

## 8. MCP

- [ ] 在“设置 > AI”添加绝对路径
      `build/msvc-static-release/ztermy_mcp_test_server.exe`。Observe 状态可发现工具但不提供
      给模型；完成 Execute 信任和精确 Schema 审核后工具才可用。
- [ ] Ask/Edit 显示精确 MCP 审批卡；Auto/YOLO 根据模式和规则直接调用，不再固定逐次
      询问。拒绝、取消、重复调用和 Schema 变化不会产生重复副作用。
- [ ] 禁用、删除、使测试 Server 崩溃并重启。预期工具立即撤销，没有残留 Pending 卡片、
      UI 卡死或应用崩溃。

## 9. 历史、诊断与重启

- [ ] 开启加密 AI 历史，重启后恢复对话；关闭保留后新消息不再写入，但已有历史仍可导出
      或删除。恢复只包含用户/助手消息，不恢复旧审批、预算或待执行工具。
- [ ] 便携版锁定保险库时历史不可见；解锁后恢复。迁移凭据存储后同一历史仍可读取。
- [ ] 临时开启“完整 AI 请求和响应 Trace”并发送一次可丢弃请求。预期 JSONL 包含有界的
      请求、终端上下文、工具续轮和原始响应，但没有 Authorization Header 或 API Key；
      关闭后停止记录。普通日志仍不包含对话正文。

## 10. 安装包与最终外观

- [ ] 解压便携 ZIP，确认 `portable.flag` 存在；运行、保存设置、关闭、重开，数据留在便携
      目录且不缺 DLL。
- [ ] 在 Windows 11 和 Windows Sandbox 安装 MSI、启动、升级/覆盖安装、卸载。首次配置
      Windows Installer 可以较慢，但不能永久卡住；卸载后应用文件与快捷方式移除，用户
      数据按产品约定保留。
- [ ] 检查浅色/深色、100%/125%/150%/200% DPI、键盘 Tab 顺序、屏幕阅读器名称、Mica/
      Acrylic/Transparent 和终端背景。预期无裁剪、错色、模糊品牌图或不可达控件。
