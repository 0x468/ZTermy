# 自定义主题

可直接导入的原创示例：[Violet Dusk](examples/themes/violet-dusk.json)。

## 导入与使用

1. 打开设置 → 外观 → 主题，在内嵌主题库中导入主题文件。
2. 选择跟随系统（浅色/深色各一套）或固定主题。悬停/Tab 聚焦仅更新旁边的窗口预览；点击或 Enter / Space 选中卡片才预览整个应用。
3. 设置页“应用”保存主题；“放弃更改”或离开设置页恢复已保存的主题。
4. “结束预览”回到当前草稿的模式规则；“放弃更改”恢复已保存方案，包含两个系统主题槽位。

逐行“恢复默认”只改变草稿，仍需设置页“应用”。导入、移除属于主题库文件操作，立即生效，不受“放弃更改”撤销。内置主题不能移除。主题同时决定顶栏、侧栏、内容页和浮层颜色；默认强调色保持紫色，可明确选择“跟随主题”。

导入的主题位于应用实际 settings.json 同级的 `themes/<id>.json`，隔离实例则位于其 `--data-dir` 对应的数据目录。建议通过导入使用；手工放入该目录需重启加载，并保证文件名与 JSON 的 id 一致。

## ztermy JSON 字段

| 字段 | 说明 |
| --- | --- |
| `version` | 示例格式版本为 1；当前解析器尚未据此拒绝未来版本，请使用 1 |
| `id` | 非空、小写 ASCII 字母/数字、单个连字符分隔；保存后的 ID 最长 64 字符 |
| `name` | 非空显示名称，可用中文 |
| `dark` | 可选布尔值；省略时按背景亮度判断，用于工作区标题、工具栏等文字配色 |
| `background`、`foreground` | 必填，终端默认背景和前景 |
| `cursor` | 可选，省略时使用 foreground |
| `selectionBackground` | 可选，默认 `#2A5B91` |
| `selectionForeground` | 可选，默认 `#FFFFFF`；建议与选区背景一并指定 |
| `accent` | 可选，空字符串表示无强调色建议；仅在应用强调色选择“跟随主题”时采用 |
| `ansi` | 必填，16 色对象，键名见示例，必须全部提供 |

颜色采用六位 RGB 十六进制，推荐 `#RRGGBB`；不支持 alpha、三位缩写或颜色名称。透明度由应用设置控制。主题改变默认色与前 16 个 ANSI 色，保留终端 256 色表的其余部分；程序显式输出的真彩色不会自动替换成主题色。

导入时会规范化并截短 ID；重名追加 `-2`、`-3` 等后缀，后缀包含在 64 字符上限内，不覆盖已有主题。较早版本导入的超长 ID 主题可重新导入获得可保存的 ID。

## 其它导入格式

- Windows Terminal：单个 scheme JSON，或含 `schemes` 数组的 JSON 对象。需要名称、默认前景/背景和全部 16 个色值；紫色键为 `purple` / `brightPurple`。当前使用严格 JSON，带注释或尾逗号的 JSONC settings.json 需先转换。
- Ghostty：`key = value` 文本，必须含 background、foreground 和 `palette = 0=...` 至 `palette = 15=...`。支持 cursor-color、selection-background、selection-foreground。当前只接受六位十六进制颜色；并非完整 Ghostty 配置解析器。

## 本轮手动检查

- Tab 能到达主题模式、主题卡和逐行重置；Enter/Space 可操作，焦点框可见。
- 保存 Nord 后，逐行恢复默认再“放弃更改”，应回到 Nord；重启仍为 Nord。
- 悬停卡片只更新局部预览；选择卡片后应用整体变色，放弃恢复已保存方案。
- 跟随系统分别保存浅色与深色主题，切换 Windows 明暗后应用和终端一起变化；固定主题不随系统变化。
- 在隔离数据目录模拟设置保存失败，放弃草稿应恢复原主题。不要修改正式数据目录的权限。
- 将示例 id 改为超过 64 个小写英文字母，连续导入两次；两个导入结果应可分别应用并重启保留。

以上包含需要实机观察的验收步骤，构建与自动检查结果以本轮交付记录为准。
