# Ztermy C++ 工程规范

本规范补充 clang-format、clang-tidy 和编译器无法完整表达的工程约束。它适用于新代码；旧代码在相关功能变更时渐进收敛，不以一次性大重构阻塞产品迭代。

## 1. 文件与类规模预算

- 头文件建议不超过 400 行，实现文件建议不超过 1200 行，QML 页面建议不超过 1000 行；超过预算必须在评审中说明原因和拆分计划。
- 单个函数建议不超过 80 行；复杂状态机可超过，但状态、转换和副作用必须可独立测试。
- 类应只有一个主要变化原因。连接、持久化、列表投影和 QML 编排不得继续汇集到 `AppController`。
- 新功能优先建立领域/应用服务，由 `AppController` 暴露窄接口；不得为了少建文件而扩大万能控制器。
- 文件大小是审查触发器而不是机械失败条件。拆分后若增加循环依赖、重复状态或隐式生命周期，则保留原结构并记录 ADR/评审说明。
- `ztermy_code_structure_gate` 对规模债务采用棘轮：基线内旧文件只能缩小不能增长，新文件必须直接满足预算；
  `ztermy_code_health_report` 刷新可审阅的规模与直接 include 依赖报告。

## 2. 分层与依赖方向

- `domain` 只表达业务数据、算法和状态，不依赖 QML、窗口或平台 API；能不用 Qt 类型时使用标准库类型。
- `application` 编排用例、并发和生命周期，可依赖领域与抽象接口，不直接散落 Win32 细节。
- `infrastructure` 实现文件、网络、SSH、系统配置等边界；解析不可信输入时有尺寸和数量上限。
- `ui/qml` 负责呈现与轻量交互胶水，不拥有持久化真源、后台线程或 SSH 状态机。
- `platform/windows` 封装 Win32、ConPTY、凭据管理器、通知区、窗口材质和命中测试；上层通过窄接口使用。
- 顶层窗口的最小化、最大化/还原和唤出只能经由 `core/windowing`（C++ 调 `ztermy::windowing::present/minimize/toggleMaximize`，QML 调 `WindowControl` 单例）；
  `QWindow::show*()` 会整体覆盖窗口状态并丢失最大化标志，`src/` 内除 `WindowStateRuntimeSmoke.h` 的命名 smoke 辅助函数外禁止直接调用，由 `ztermy_code_structure_gate` 检查（ADR 0051）。
- 禁止反向依赖和跨层“顺手 include”。新增依赖必须能解释其所有权和替换边界。
- 自动门禁禁止 `core` 反向依赖上层、`domain` 依赖 application/infrastructure/platform/ui，以及
  `infrastructure` 依赖 application/ui；无法由直接 include 扫描表达的运行时依赖仍由评审负责。

## 3. 所有权、RAII 与生命周期

- 默认值语义；需要唯一所有权时用 `std::unique_ptr`，共享生命周期确有必要时才用 `std::shared_ptr`。
- QObject 父子所有权和智能指针只选一个主所有者，禁止双重释放或靠注释维持生命周期。
- 跨线程回调捕获 QObject 时使用 `QPointer` 或明确的停止/等待协议，不捕获裸 `this` 后任由任务越过析构。
- 文件、socket、线程、事件句柄和 libssh2 资源必须由 RAII 对象管理。
- 析构和 shutdown 必须幂等、可取消并有上界；不得依赖进程退出回收活动线程。

## 4. 线程与 UI 边界

- 文件、网络、SSH、SFTP、模型请求、历史索引和重计算不得阻塞 GUI 或 Qt Quick render thread。
- 工作线程只处理其拥有的数据快照；通过 queued signal/invoke 把不可变结果交回 UI 线程。
- 不在锁内发信号、调用 QML、等待网络或执行用户回调。
- 每个后台任务明确取消、超时、过期结果丢弃和析构等待策略。
- 高频终端路径避免每字节 signal、无界队列、每单元 QML 对象和不必要的深复制。

## 5. 错误与状态建模

- 可恢复失败使用 `std::expected<T, Error>` 或显式状态类型；`bool` 只用于含义显而易见且调用者不需要原因的操作。
- 错误枚举表达机器可判断的类别，用户文案在应用/UI 边界翻译；不得解析错误字符串决定控制流。
- 异步操作至少区分 idle、running、success/ready、failed 和 cancelled；避免多个布尔值组成非法状态。
- 不吞掉保存、迁移、连接和凭据错误。失败时保留上一份可用状态，除非契约明确要求清空。
- 不用异常表达常规 I/O 失败；资源耗尽等异常必须在线程边界收敛为明确失败。

## 6. 接口、include 与编译边界

- 头文件只暴露必要类型，优先前置声明；实现细节放 `.cpp` 或私有实现对象。
- 参数默认 `const T&` / `std::span` / `std::string_view`；需要接管所有权时按值传入并 move。
- 返回借用对象时让生命周期在类型或命名上清楚；禁止返回临时对象视图。
- QML API 使用稳定、有限、可测试的属性和命令，不暴露可任意修改的内部容器。
- 新模块按职责建 CMake target，依赖使用 target-scoped 属性；避免把所有实现继续加入主可执行文件。

## 7. 持久化与兼容性

- 每个存储拥有独立、单调递增且永不复用的 schema 版本。
- 新字段必须保留立即前一真实版本 fixture，并验证读取、默认值、重写和未知未来版本拒绝。
- 原子保存；适合用户长期数据的存储使用 last-known-good/备份恢复策略。
- 密码、passphrase、私钥内容和 API key 不进入普通 JSON、日志、trace 或崩溃诊断。
- 删除功能时保留已发布 schema 的可读墓碑路径，不回退版本号。

## 8. 行为测试策略

- 修 bug 时先写能复现症状的回归测试；不适合单元测试的原生/UI 行为记录可重复的 runtime smoke。
- 迭代时运行受影响 target、聚焦 CTest、格式和相关 QML/翻译/资产门禁。
- 功能提交运行所属模块及相邻集成测试；里程碑执行 Debug 和 static Release 全量矩阵。
- 测试行为契约而非私有实现，不因重构而大面积重写测试。
- UI 测试覆盖空、加载、错误、成功、窄宽度、键盘焦点以及深浅主题关键状态。

## 9. 性能证据

- 优化前固定场景、机器/虚拟机环境、构建类型和指标，再记录基线。
- 报告 p50/p95/p99、最大 UI heartbeat gap、帧交换、内存或队列上限；不以主观“更快”代替数据。
- Debug 适合诊断正确性，Release 用于用户可感知延迟和渲染结论。
- 禁止靠删除材质、动画或功能伪装优化；降级模式必须是明确产品选项。
- 任何缓存都有失效规则和容量上限，任何 fanout 队列都有背压、合并或丢弃语义。

## 10. Windows 平台隔离

- Win32 消息、HRESULT、句柄、DPI、材质、托盘、Snap Layouts 与 ConPTY 逻辑留在平台层。
- UTF-16/UTF-8 和终端字节编码在边界显式转换；不得假设系统代码页。
- 本机特性检测失败时显式降级，不把 Windows 版本号当作唯一能力判断。
- COM、窗口句柄和线程亲和资源记录创建/销毁线程与错误传播。

## 11. 日志与诊断边界

- 日志记录操作类别、阶段、耗时、状态和脱敏标识，不记录密码、passphrase、私钥、终端输入或未脱敏命令行。
- 高频路径使用分类和采样，避免格式化巨量字符串后才判断日志级别。
- 调试 trace 有显式开关、大小上限、位置提示和关闭/清理路径。
- 用户可操作错误进入 UI；内部诊断进入 logging category，二者不互相替代。

## 12. 变更规模与评审清单

- 使用小而可回滚的 Conventional Commit；机械重命名/移动与行为修改尽量分开。
- 改动前确认真源、调用路径、所有者和持久化边界；改动后检查 blast radius。
- 评审必须回答：线程在哪里、谁拥有对象、失败保留什么、是否改 schema、是否影响 QML/翻译/资产、如何回归、如何人工验收。
- 不顺手覆盖用户未提交改动，不用 destructive Git 命令清理工作树。
- 重大且持久的技术/产品契约写 ADR；普通实现细节留在代码和测试中。
